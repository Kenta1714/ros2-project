# 人物を検出したら停止する巡回ロボット

## 目的
壁と箱のある部屋で低速走行し、搭載カメラに人が見えたら停止する。画像認識の結果をロボットの行動判断に接続することを目的とした。部屋全体の探索完了や実機安全性を目標には含めない。

## 構成とAIの入出力
ROS 2 Humble、Gazebo Classic 11、教材のHappy Miniを使用。YOLOv8nはCOCO事前学習済み重みを使い、追加学習なし、CPUで推論する。入力は搭載RGBカメラの640×480画像。出力は人物クラス0の検出枠と信頼度スコア。信頼度0.5以上を人物ありとし、異なるタイムスタンプの2画像で連続検出すると停止状態を保持する。スコアは正解率ではない。

## 動作と工夫
通常は0.08 m/sで前進する。LiDAR前方0.6 m未満で左右の空き具合に応じて旋回するルール制御を採用。LaserScanの角度情報を使い、固定の配列添字には依存しない。人物の座標や時刻を停止条件には使用しない。

カメラ位置を調整して車体の映り込みを減らした。検出と制御を別プロセスに分け、最新画像1枚だけを保持することで古い画像の蓄積を避けた。重複stampを連続検出として数えず、人物なしで連続回数をリセットする。モデル初期化中、画像・推論結果の途絶、LiDARの途絶・有効観測なしでは速度をゼロにする。監視は単調時刻。停止後は自動再開せず再起動でリセットする。

独自の部屋、箱、人物配置を用意し、全体像と検出枠付き画像、状態を動画に記録した。人物は固定位置でアニメーションするGazebo標準actor。物理的な接触形状を同位置に別途追加した。観察用固定カメラは制御に使用しない。

## 結果
同じ初期条件から2回、巡回→箱の回避→人物の連続検出→停止保持を確認した。1回目は観測開始36.313秒で停止、判定2画像のスコアは0.8733と0.8057。2回目は38.892秒で停止、0.8793と0.8837。いずれも異なる画像stampである。

停止後の速度指令はゼロを保持した。停止3秒後以降のオドメトリ最大並進速度は1回目0.000903 m/s、2回目0.001823 m/s。停止保持はそれぞれ48秒以上、51秒以上観測した。走行とGazebo同時実行時のCPU推論時間は記録された有効結果で約0.15〜0.90秒。ソフトウェア描画ではシミュレーション時間の進みは実時間より遅い。

別途、制御単体で初期化待ち、センサー・推論結果途絶、無効な距離、重複画像、単発検出、2画像検出、停止保持を確認した。実走の生観測を間引いたログとsummary.jsonをvalidation/patrolに保存した。

## 制限・改善点
人物モデル1種類・限定した照明と配置での確認。一般的な人への認識性能、部屋全体の探索、実機の安全性は未検証。無衝突判定の接触センサー試験は行っていない。LiDARやカメラのプロセスを実走中に個別停止する障害注入試験は未実施であり、途絶時の停止は制御単体で確認した。今後は異なる配置・人物、処理遅延、通信断の評価が必要。
